# XetFS FSKit prototype

This macOS 27 prototype implements FSKit's unary resource and volume protocols in
Rust and uses a small Swift extension entry point. It remains experimental:
there is no signed or enabled extension and no real mounted-filesystem
acceptance yet. Do not migrate the Codex directory or use the prototype for
unique data until those checks pass.

The source URL must identify an existing XetFS repository and remain separate
from the empty mountpoint. The extension receives a security-scoped URL and
holds that scope for the volume lifetime. The volume identifier is persisted
inside the repository and stays stable when its directory moves.

Extended attributes, creation times and the macOS hidden flag are stored in
the v4 repository format, including snapshots; v1 through v3 repositories are
rejected and require their original version. Other file flags are rejected. Current limitations
include ACL enforcement, file locking, real kernel permission
checks, behavior during forced termination, and complete FSKit directory-cookie
and object-lifetime validation. The existing storage engine stages a full file
for writes and commits the file on each FSKit write. Each write currently
reconstructs and rechunks the entire file, so small writes to large files can
require substantial temporary space and I/O. Per-file allocated size is reported
as logical size; use repository statistics for stored object bytes. Read-only mounts are
rejected explicitly. Creation rejects attributes the adapter cannot apply.

```sh
cargo test --locked --manifest-path macos/Cargo.toml --test volume
macos/extension/build-unsigned.sh /path/to/new/output-directory
# Once both authorized profiles and an identity exist:
python3 macos/extension/sign.py /path/to/unsigned/XetFS.app /path/to/new/signed-output IDENTITY_SHA1 /path/to/host.provisionprofile /path/to/extension.provisionprofile
# After signing and activation, mount only a fresh empty test directory:
cargo run --locked --manifest-path macos/Cargo.toml --bin mount-directory -- /path/to/repository /path/to/empty/mountpoint
python3 macos/scripts/validate_mount.py /path/to/empty/mountpoint
```

The mount validator checks basic I/O, fsync, mmap, links, xattrs, open-unlink,
flock, SQLite locking and a local Git workflow in a temporary directory. It
requires an empty mounted XetFS volume and deletes only its own test directory.
A passing run is one acceptance step, not a full crash or permission audit.

The build creates an unsigned `.app` containing the FSKit `.appex`. It does not
install, register, sign, or mount anything. Before real mounting the extension
requires a valid Apple signing identity, a provisioning profile authorized for
`com.apple.developer.fskit.fsmodule`, compatible bundle IDs, and explicit
extension activation. The host displays activation instructions. Apple's
`mount -F -t xetfs REPOSITORY MOUNTPOINT` route accepts a chosen directory. The
Rust `mount-directory` wrapper refuses nonempty or overlapping paths and uses
that route. This route still requires a signed, enabled extension and has not
yet been tested with a real FSKit mount. `extension/entitlements.plist` records the requested
entitlements; it is not a substitute for an authorized profile. The signing
helper checks profile team, expiration, exact bundle IDs, the extension FSKit
entitlement and certificate membership before signing a fresh copy. It has
not yet been exercised with real authorized profiles.

The experimental `import-directory SOURCE NEW_REPOSITORY` binary copies a
quiescent directory into a new repository. It preserves supported xattrs, hard
links, ownership, mode, modification/access/birth times and the hidden flag.
It rejects ACLs, other flags, special files, nested filesystems and detected
source changes. It also rejects hard links with names outside the source tree.
Change time is generated by XetFS. A failed import leaves `IMPORT_INCOMPLETE`;
normal repository open and FSKit probing reject that repository. Do not remove
the marker or use this importer for a live or irreplaceable directory. The importer groups small files from each directory into bounded shared Xorbs.
It checks repository integrity and compares the imported namespace,
file bytes, links and supported metadata against the source before clearing
the marker. The read-only `--check` reports unsupported metadata and external hard links
before import and checks that regular files can be opened; it does not freeze
the source. `--resume` accepts only a repository with an incomplete-import
marker bound to the original source directory. It clears the partial namespace,
reuses durable chunks, then imports and verifies the full source again. If the
process stopped before recording source identity, create a new repository. It does not create a source snapshot.

```sh
cargo run --locked --manifest-path macos/Cargo.toml --bin import-directory -- --check /path/to/source
cargo run --locked --manifest-path macos/Cargo.toml --bin import-directory -- /path/to/quiescent/source /path/to/new/repository
cargo run --locked --manifest-path macos/Cargo.toml --bin import-directory -- --resume /path/to/quiescent/source /path/to/incomplete/repository
```
